# JARVIS — архитектура

## Стек

| Слой | Технология | Почему |
|---|---|---|
| Оболочка | Tauri v2 (2.12), WebView2 | нативное окно, малый размер, без Electron/Node-рантайма |
| Нативный слой | Rust + `windows` 0.62 (Win32, COM, WinRT) | прямой доступ к Core Audio, GSMTC, UIA, WMI |
| Асинхронность | Tokio | сеть, процессы, таймауты, отмена |
| UI | React 19 + TypeScript + Motion 14 | пружинная анимация формы острова |
| Хранение | SQLite (`rusqlite`, bundled) | история, задачи, настройки |
| Секреты | Windows Credential Manager (`CredWriteW`) | ключи API не попадают на диск в открытом виде |

Python и Electron не используются. Node.js нужен только для сборки фронтенда.

## Агент

Характер: системный промпт описывает Джарвиса как собеседника (тёплый,
остроумный, со своим мнением, честный, помнит пользователя через
`memory_save`), блок «предпочтения пользователя» берётся из настроек
«Характер» (имя, «ты»/«вы», манера). В голосовом режиме — разговорная речь,
интонация через пунктуацию, всё произносимое пишется словами.


Один ход: контекст (время, активное окно, недавние окна, папки, память) →
модель с инструментами → для каждого вызова: разбор аргументов, оценка риска
по аргументам и политике (вложения, приватность, имена элементов UIA) →
подтверждение при необходимости → выполнение с таймаутом и отменой →
результат `{ok, summary, data}` обратно модели. Ошибки возвращаются модели
для восстановления (до `max_steps`). Независимые безопасные вызовы идут
параллельно. Ход завершает только модель — ответом без вызовов
инструментов: досрочный выход после первого успешного шага обрывал
запросы вида «открой X и сделай Y». Лимит провайдера (429 +
`Retry-After`) выдерживается: ожидание, выученный лимит в минуту,
равномерная подача запросов, обратный отсчёт в UI.

Риск: **low** — сразу; **moderate** — подтверждение (по умолчанию, один раз
на инструмент в разговоре); **high** — подтверждение всегда. Решения и
выполнения moderate/high пишутся в `audit_log`.

## MCP

Серверы хранятся в `kv` (`mcp.servers`), их последние списки инструментов — там же
(`mcp.tools`), поэтому агент знает инструменты, не запуская серверы. Инструмент
называется `mcp__<сервер>__<инструмент>` (до 64 символов). `Registry` отдаёт их
вместе со встроенными и выполняет через `Hub::call`. Первый вызов запускает
сервер: `initialize` → `notifications/initialized`, затем `tools/call`. Сервер,
к которому не обращались 10 минут, останавливается. stdio-сервер работает в
Job Object без консольного окна. Команда ищется в PATH так же, как в cmd
(`npx` → `npx.cmd`), `%VAR%` в аргументах раскрываются. HTTP-клиент ведёт
`Mcp-Session-Id` и `MCP-Protocol-Version`, принимает ответ JSON или SSE и
переподключается, если сервер забыл сессию. Сервер может прислать
`tools/list_changed`, тогда список перечитывается. На `ping` и `roots/list` клиент
отвечает, остальные запросы сервера отклоняет. Риск: `readOnlyHint` → low,
`destructiveHint` → high (подтверждается всегда), иначе moderate. OAuth и старый
транспорт SSE не поддерживаются.

## Голос

Два движка с общим UI острова (события `voice:state`, `voice:level`,
`voice:transcript`):

**Локальный (по умолчанию), sherpa-onnx на CPU.** cpal: микрофон → моно →
фильтр + ресемплинг → PCM16 16 кГц чанками по 100 мс → Silero VAD (нейросетевой;
пауза внутри фразы до 0,9 с не режет её, шум и музыка — не речь) → GigaAM v3
(RNN-T от Сбера для русской речи, с пунктуацией; 0,2–0,6 с на фразу) →
`Agent::voice_turn`: обычный ход агента (тот же промпт с припиской «ответ будет
озвучен», инструменты, подтверждения, история чата) → текст ответа стримится в
`PhraseSplitter` → по готовым предложениям синтез Supertonic 3 (10 голосов,
5 шагов flow matching) или Piper → ресемплинг 24 кГц → очередь вывода. Начало
речи пользователя поверх ответа очищает очередь (перебивание); новая просьба во
время хода ждёт его окончания (последняя побеждает); «стоп»/«хватит» отменяют
всё; фраза, начатая меньше чем через ~2 с паузы, продолжает предыдущую и
объединяется с ней. Перед синтезом текст нормализуется (`ru_speech`), после
каждой фразы — пауза по её знаку препинания. Распознаватель держится в
памяти 3 минуты после сессии и выгружается.

Отклик на имя: сессия живёт в двух режимах — ожидание (`dormant`: остров
закрыт, уровни не шлются, фразы без имени отбрасываются молча) и разговор.
Переход по имени в начале фразы (`wake::addressed`), Ctrl+Alt+K или кнопке;
обратно — «стоп»/«хватит», Esc или минута тишины. Микрофон не переоткрывается
между режимами. Если открыть его не удаётся, слушатель повторяет попытки
с нарастающей паузой, не показывая ошибку.

Модели не входят в установщик: «Настройки → Голос» скачивает их из релизов
sherpa-onnx на GitHub (`asr-models`, `tts-models`) с проверкой размера и
SHA-256 (из API релизов) и распаковывает `.tar.bz2` с защитой от выхода за
папку. sherpa-onnx открывает файлы по ANSI-пути — для профилей с кириллицей
используется короткий путь 8.3.

Почему не Whisper: первая версия на whisper.cpp (small) на живой речи давала
«Настой, пожалуйста, браузер» вместо «Открой…» и «Джарби» вместо «Джарвис»;
turbo без видеокарты распознавал фразу 18 с.

**Qwen Omni Realtime.** Те же чанки → `input_audio_buffer.append`. Ответ
`response.audio.delta` (PCM16 24 кГц) → очередь. `speech_started` очищает
очередь и отправляет `response.cancel`. Функции голосовой модели исполняются
тем же реестром и политикой риска; многошаговые задачи уходят в текстового
агента через `delegate_to_agent`.

Эхо-гейт (оба движка) глушит тихий сигнал микрофона, пока Джарвис говорит
через колонки; локальный VAD в это время засчитывает речь, только если она
на 12 дБ громче фона, а фразы, не прошедшие этот порог, отбрасывает.

## Окно-остров

* Одно прозрачное окно-холст 640×600 логических px, верх-центр рабочей
  области основного монитора; `WS_EX_TOOLWINDOW` (нет в панели задач),
  `WS_EX_TOPMOST`, `WS_EX_NOACTIVATE` (через `focusable=false` в tao),
  без скругления и рамки DWM.
* **Прозрачные области не блокируют клики**: окно по умолчанию
  `WS_EX_TRANSPARENT` (`set_ignore_cursor_events(true)`). Поток
  `island-tracker` читает `GetCursorPos` и включает интерактивность, только
  когда курсор над текущей формой острова. Форму присылает фронтенд при
  смене состояния (целевой прямоугольник, не каждый кадр).
  Интервал опроса адаптивный: 16 мс рядом с островом, 40 мс в 120–400 px,
  100 мс дальше, 250 мс когда остров скрыт. Низкоуровневый хук мыши
  отвергнут: он стоит в пути каждого движения мыши во всей системе.
* **Перетаскивание файлов**: нажатая кнопка мыши вне острова + курсор в зоне
  приближения → окно временно становится интерактивным, и OLE drag-drop
  доходит до WebView2 (Tauri `onDragDropEvent`). Перетаскивание окон
  (`GUI_INMOVESIZE`) исключено.
* **Фокус**: клики по кнопкам острова не забирают фокус. Рабочее
  пространство вызывает `begin_input` (запоминает предыдущее активное окно,
  делает окно фокусируемым) и `end_input(restore)` (возвращает фокус,
  только если он всё ещё у острова).
* **Полноэкранные приложения**: хук `EVENT_SYSTEM_FOREGROUND` + таймер
  1,5 с + `SHQueryUserNotificationState` → остров скрывается.
* **Дисплеи**: скрытое top-level окно ловит `WM_DISPLAYCHANGE` и
  `WM_SETTINGCHANGE(SPI_SETWORKAREA)`; смена DPI — через
  `ScaleFactorChanged`. Перерасчёт позиции с дебаунсом 400 мс.

## Фронтенд (src)

```
island/     Island.tsx (форма, пружины, контроллер), Eyes.tsx, geometry.ts, views/
workspace/  чат: стриминг, строки инструментов, подтверждения, вложения
store/      zustand: island (режимы), system (медиа/звук/яркость), agent
lib/        типизированные обёртки IPC и событий
ui/         Icon (свой набор), Slider
```

Режим острова выводится из фактов (`hovered`, `dragOver`, `workspaceOpen`,
`voiceOpen`), а не хранится отдельно — у каждого перехода один владелец.

## Принципы

* Каждое действие проверяется чтением результата (громкость читается
  обратно, запуск приложения ждёт его окно, WM_CLOSE проверяет, закрылось ли
  окно).
* Блокирующие вызовы Windows — только в `platform::blocking` (пул Tokio +
  COM MTA на потоке).
* Ошибки сериализуются как `{ code, message }` с русским текстом без
  технических трассировок; детали — в журнале
  `%LOCALAPPDATA%\dev.jarvis.desktop\logs\jarvis.log`.
