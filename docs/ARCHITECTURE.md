# JARVIS — архитектура

## Стек

| Слой | Технология | Почему |
|---|---|---|
| Оболочка | Tauri v2 (2.12), WebView2 | нативное окно, малый размер, без Electron/Node-рантайма |
| Нативный слой | Rust + `windows` 0.62 (Win32, COM, WinRT) | прямой доступ к Core Audio, GSMTC, UIA, WMI |
| Асинхронность | Tokio | сеть, процессы, таймауты, отмена |
| UI | React 19 + TypeScript + Motion 14 | пружинная анимация формы острова |
| Хранение | SQLite (`rusqlite`, bundled) | история, задачи, настройки |
| Секреты | Windows Credential Manager (`CredWriteW`) | ключи API не попадают на диск в открытом виде |

Python и Electron не используются. Node.js нужен только для сборки фронтенда.

## Модули (src-tauri/src)

```
platform/     нативные интеграции, ничего не знают об UI и агенте
  island.rs     окно-остров: стили Win32, размещение, hit-test, фокус
  watcher.rs    поток с циклом сообщений: WinEvent foreground, WM_DISPLAYCHANGE
  display.rs    мониторы, DPI, полноэкранный режим
  audio.rs      IAudioEndpointVolume, ISimpleAudioVolume
  brightness.rs WMI (встроенная панель), DDC/CI (внешние мониторы)
  media.rs      GSMTC: метаданные, обложка, управление, события
  winmgr.rs     окна: перечисление, фокус, сворачивание, закрытие (WM_CLOSE), snap
  apps.rs       индекс приложений (shell:AppsFolder + ярлыки Пуска), запуск с проверкой
  process.rs    имя/путь процесса по PID
ipc.rs        тонкие Tauri-команды поверх platform
state.rs      общие Arc-хэндлы
```

Следующие слои (по мере реализации): `store/` (SQLite, Credential Manager),
`ai/` (провайдеры), `tools/` (реестр инструментов), `agent/` (цикл
Observe → Reason → Act → Verify → Report), `voice/`.

## Окно-остров

* Одно прозрачное окно-холст 640×600 логических px, верх-центр рабочей
  области основного монитора; `WS_EX_TOOLWINDOW` (нет в панели задач),
  `WS_EX_TOPMOST`, `WS_EX_NOACTIVATE` (через `focusable=false` в tao),
  без скругления и рамки DWM.
* **Прозрачные области не блокируют клики**: окно по умолчанию
  `WS_EX_TRANSPARENT` (`set_ignore_cursor_events(true)`). Поток
  `island-tracker` читает `GetCursorPos` и включает интерактивность, только
  когда курсор над текущей формой острова. Форму присылает фронтенд при
  смене состояния (целевой прямоугольник, не каждый кадр).
  Интервал опроса адаптивный: 16 мс рядом с островом, 40 мс в 120–400 px,
  100 мс дальше, 250 мс когда остров скрыт. Низкоуровневый хук мыши
  отвергнут: он стоит в пути каждого движения мыши во всей системе.
* **Перетаскивание файлов**: нажатая кнопка мыши вне острова + курсор в зоне
  приближения → окно временно становится интерактивным, и OLE drag-drop
  доходит до WebView2 (Tauri `onDragDropEvent`). Перетаскивание окон
  (`GUI_INMOVESIZE`) исключено.
* **Фокус**: клики по кнопкам острова не забирают фокус. Рабочее
  пространство вызывает `begin_input` (запоминает предыдущее активное окно,
  делает окно фокусируемым) и `end_input(restore)` (возвращает фокус,
  только если он всё ещё у острова).
* **Полноэкранные приложения**: хук `EVENT_SYSTEM_FOREGROUND` + таймер
  1,5 с + `SHQueryUserNotificationState` → остров скрывается.
* **Дисплеи**: скрытое top-level окно ловит `WM_DISPLAYCHANGE` и
  `WM_SETTINGCHANGE(SPI_SETWORKAREA)`; смена DPI — через
  `ScaleFactorChanged`. Перерасчёт позиции с дебаунсом 400 мс.

## Фронтенд (src)

```
island/     Island.tsx (форма, пружины, контроллер), Eyes.tsx, geometry.ts, views/
workspace/  чат: стриминг, строки инструментов, подтверждения, вложения
store/      zustand: island (режимы), system (медиа/звук/яркость), agent
lib/        типизированные обёртки IPC и событий
ui/         Icon (свой набор), Slider
```

Режим острова выводится из фактов (`hovered`, `dragOver`, `workspaceOpen`,
`voiceOpen`), а не хранится отдельно — у каждого перехода один владелец.

## Принципы

* Каждое действие проверяется чтением результата (громкость читается
  обратно, запуск приложения ждёт его окно, WM_CLOSE проверяет, закрылось ли
  окно).
* Блокирующие вызовы Windows — только в `platform::blocking` (пул Tokio +
  COM MTA на потоке).
* Ошибки сериализуются как `{ code, message }` с русским текстом без
  технических трассировок; детали — в журнале
  `%LOCALAPPDATA%\dev.jarvis.desktop\logs\jarvis.log`.
