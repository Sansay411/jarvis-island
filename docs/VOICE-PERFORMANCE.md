# Голос и отзывчивость: проверка 22 октября 2026

## Исправления

- Звук приходит окнами 32 мс вместо 100 мс; очередь ограничена 256 мс вместо 6,4 с. Кадры старше 250 мс отбрасываются. При разрыве потока VAD сбрасывает незавершённую фразу, отсутствие кадров запускает переподключение.
- Пока Jarvis ждёт имя, короткий префикс речи проверяется до окончания команды. Интерфейс открывается раньше; выполнение действия по-прежнему ждёт полную фразу. Поддерживаются короткое обращение «Джар», цепочка «Эй, Джарвис» и проверенные ошибки распознавания имени. Похожие слова и упоминание имени в длинном сообщении не активируют помощника.
- Минимальная длительность речи 120 мс вместо 250 мс позволяет не пропускать короткое «Стоп». Пауза окончания 900 мс сохранена, чтобы не резать мысль посередине.
- Распознавание и выбранный голос остаются загруженными между сессиями. Короткие ответы кешируются в памяти с ограничением размера. Прерванные задания синтеза пропускаются, новая реплика не ждёт старую очередь.
- Старая сессия не может удалить новую. Новая команда после уже произнесённого ответа не склеивается с предыдущим действием.
- Короткие точные команды громкости, яркости и мультимедиа выполняются локально. Ответ о громкости содержит проверенное значение без озвучивания технического названия устройства.
- Чат прогревается в фоне и сохраняет черновик при закрытии. Убраны анимация размытия и задержка появления текста, ускорены пружина формы и реакция на наведение. Скрытый чат не принимает фокус.
- Команды, пришедшие во время холодного запуска, ждут регистрации слушателей интерфейса. Фиксированная задержка запуска больше не используется для доставки CLI-команд.
- При получении запоздалого события потери фокуса проверяется фактическое активное окно, чтобы не закрыть уже повторно открытый чат.
- Ошибка фонового микрофона видна на острове. Повторные подключения идут через 5–30 с вместо интервалов до 5 минут. Зависшее открытие одного устройства не запрещает выбрать другое и не создаёт бесконечное число зависших потоков для той же пары устройств.

## Выявленный сбой Windows и текущая сессия

На этой машине открытие Fifine зависло внутри Windows. Службы Windows Audio и Audio Endpoint Builder работают, устройство перечисляется и отдаёт формат 48 кГц, 2 канала. Отдельный тест CPAL завис при построении потока; аналогично в тесте встроенного Intel-микрофона.

Для отделения библиотечной ошибки от Windows добавлен `wasapi_probe`: он напрямую вызывает `IAudioClient::Initialize` в совместном режиме, без CPAL, модели, интерфейса и чтения/сохранения образцов звука. В текущем состоянии Windows этот вызов тоже не вернулся. Зависшие диагностические процессы завершены после проверки.

На финальном запуске в 13:40:04 UTC Fifine подключился: `audio devices opened ms=4935`, затем `local voice session started ... dormant=true`. Захват восстановился после перезапуска приложения, настройка отклика на имя включена. Сквозной голос с фразами, произнесёнными человеком на финальной сборке, пока не подтверждён. Зависание Windows ранее воспроизведено, поэтому безотказное подключение при каждом запуске не заявляется. Если оно повторится, переподключить Fifine; если захват не восстановится, перезапустить Windows Audio с правами администратора либо перезагрузить компьютер.

После подключения были отдельные предупреждения CPAL `A buffer underrun or overrun occurred` (13:40:18 и 13:41:14 UTC), без завершения сессии по сторожевому таймеру. Устойчивость настоящего захвата ещё нельзя считать полностью подтверждённой.

Штатный перезапуск Audiosrv из текущей сессии не выполнен: есть зависимая служба Realtek, доступ к управлению службой не получен. Принудительная остановка зависимостей не применялась; аудиослужбы оставлены работающими.

После восстановления: «Джарвис», «Какая сейчас громкость», «Стоп», затем «Эй, Джарвис, какая громкость». Проверить в наушниках и с колонками отдельно. Системного AEC пока нет; эхо-гейт не гарантирует подавление любого эха.
